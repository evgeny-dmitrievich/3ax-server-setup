# 3AX Server Setup

Сценарий первоначального развёртывания **3AX-UI** на новом VPS с **Ubuntu 22.04 LTS** или **Ubuntu 24.04 LTS**.

> **Важно:** скрипт предназначен для нового сервера. Запускайте из веб-консоли/VNC хостинга, имея доступ к восстановлению системы. В первый раз рекомендуется сделать snapshot VPS. Не запускайте непроверенные скрипты от root.

## Установка одной командой

```bash
curl -fsSL https://raw.githubusercontent.com/evgeny-dmitrievich/3ax-server-setup/main/setup.sh -o /tmp/3ax-setup.sh && sudo bash /tmp/3ax-setup.sh
```

Пока файл не загружен в GitHub, команда не заработает. Лучше сначала прочитать код скачанного скрипта. Для постоянных автоматизированных развёртываний стоит фиксировать конкретный commit вместо меняющейся ветки `main`.

Скрипт в начале устанавливает `locales`, `console-setup`, `console-setup-linux`, `kbd`, включает `ru_RU.UTF-8` и устанавливает поддерживающий кириллицу шрифт Linux-консоли (Terminus / Uni2). После этого собственные сообщения и вопросы скрипта выводятся **на русском**. Однако у некоторых хостингов шрифт задаётся самим веб-интерфейсом терминала, и команды внутри Ubuntu не смогут его заменить. Для таких случаев доступен запуск с `SETUP_LANG=en` (английские сообщения скрипта). Вопросы стороннего установщика 3AX-UI по-прежнему могут быть на английском.

После подготовки локали скрипт запросит подтверждение `ДА` или `YES` и доверенный IPv4 для исключения из Fail2ban (можно оставить пустым; нужный адрес вводится вручную, чтобы не публиковать его на GitHub). Затем установщик панели задаст собственные вопросы. В актуальном установщике 3AX-UI выбирайте:

- **Debug mode:** `N` (обычная установка)
- **Customize Panel Port:** `Y`
- **Panel Port:** `13350`
- **ACME HTTP-01 port:** `80` (если выбран вариант выдачи сертификата через этот порт)

После установки скрипт проверит сервис x-ui, открытый порт 13350, WebBasePath и SSL-сертификат. Затем с помощью штатной команды `x-ui setting` назначит **новый случайный логин и пароль** и выведет их в самом конце вместе с HTTPS-ссылкой, прочитанной из SAN сертификата. Первоначальный пароль, показанный установщиком 3AX-UI, после этого перестанет действовать. Скрипт не записывает итоговый пароль в лог или GitHub. Сохраните его самостоятельно в менеджере паролей. Если проверка не пройдёт, вместо ложного успеха будет указан этап ошибки.

### Если веб-консоль по-прежнему показывает квадраты

В таком случае шрифт, вероятно, задаёт интерфейс хостинга. Запустите локальную копию скрипта в режиме ASCII/English:

```bash
sudo env SETUP_LANG=en bash /tmp/3ax-setup.sh
```

На Ubuntu 22.04/24.04 наличие `ru_RU.UTF-8` не гарантирует, что веб-консоль хостинга умеет рисовать русские буквы. Если есть возможность, используйте обычный SSH-терминал с UTF-8.

## Что настраивается

| Компонент | Настройка |
| --- | --- |
| Ubuntu | 22.04 / 24.04 |
| SSH | Добавляется 1335/tcp; прежние порты временно сохраняются |
| Fail2ban | `sshd`, 3 попытки за 600 секунд, бан 43200 секунд |
| Fail2ban ignoreip | `127.0.0.1/8 ::1` и доверенный IPv4, вводимый при запуске |
| UFW | 1335/tcp, 13350/tcp, 13133/tcp+udp, 20304/udp, 13131/udp, 80/tcp |
| Порт 443 | Не открывается |
| Основные DNS | Cloudflare: 1.1.1.1, 1.0.0.1, 2606:4700:4700::1111, 2606:4700:4700::1001 |
| Резервные DNS | Quad9: 9.9.9.9, 149.112.112.112, 2620:fe::fe, 2620:fe::9 |
| Nginx | Останавливается; вызов установки nginx в 3AX-UI отключается |
| Ядро / DKMS | linux-generic + linux-headers-generic только при совместимом generic-ядре; dkms всегда |

DNS: `FallbackDNS` в systemd-resolved применяется при отсутствии других DNS-серверов, а **не как строгая очередь после Cloudflare**. Если DHCP продолжает передавать свои DNS, нужен Netplan `use-dns: false`. Скрипт пытается изменить Netplan только при запуске **не через SSH**, при распознанной DHCP-конфигурации и с подтверждением `netplan try`. В остальных случаях записывает только настройки `systemd-resolved` и предупреждает об ограничении.

## После установки

Финальный блок выводит только результат (`Установка завершена. Ошибок нет.` либо этап ошибки), предупреждения при необходимости, URL, логин и пароль 3AX-UI. Если нет сертификата, панель не запущена или выбран неверный порт — итоговый блок покажет ошибку, а не успешный вход.

1. **Не закрывайте веб-консоль хостинга.** В новом терминале проверьте доступ `ssh -p 1335 root@IP_СЕРВЕРА` (если root-доступ по SSH разрешён). Если root запрещён, используйте созданного пользователя.
2. Убедитесь, что веб-панель открывается на фактически выбранном порту `13350` и SSL работает.
3. Только **после успешного теста нового SSH-доступа** удалите старый порт из конфигурации sshd, при наличии `ssh.socket` — из его `ListenStream`, затем из UFW. Скрипт специально **не закрывает** старый порт автоматически.
4. Проверьте `sudo ufw status verbose`, `sudo fail2ban-client status sshd`, `sudo systemctl status x-ui` и `resolvectl status`.
5. Если после обновления ядра требуется перезагрузка, проведите её после проверки доступа.

## Замечания по безопасности

- Подразумевается чистый VPS, а не уже настроенный производственный сервер.
- Дополнительные фильтры у хостинга (security groups) настраиваются отдельно: UFW их не заменяет.
- Интерфейс панели по `13350/tcp` открыт для всех IP, как в исходном наборе команд. При возможности ограничьте доступ доверенными адресами.
- Открытие UFW без сохранения старого SSH-порта способно заблокировать администрирование — поэтому ранее используемые порты сохраняются.
- Репозиторий публичный: никакие сертификаты, пароли, личные ключи и журнал с секретами сюда не загружать.
- Программа 3AX-UI загружается из стороннего репозитория `coinman-dev/3ax-ui`; перед развёртыванием в продакшене следует проверить исходники и изменения установщика. Скрипт сверяет форму вызова `install_nginx`, но это **не заменяет** аудита стороннего кода.
