# 3AX Server Setup

Сценарий первоначального развёртывания **3AX-UI** на новом VPS с **Ubuntu 22.04 LTS** или **Ubuntu 24.04 LTS**.

> **Важно:** скрипт предназначен для нового сервера. Запускайте из веб-консоли/VNC хостинга, имея доступ к восстановлению системы. В первый раз рекомендуется сделать snapshot VPS. Не запускайте непроверенные скрипты от root.

## Установка одной командой

```bash
curl -fsSL https://raw.githubusercontent.com/evgeny-dmitrievich/3ax-server-setup/main/setup.sh -o /tmp/3ax-setup.sh && sudo bash /tmp/3ax-setup.sh
```

Пока файл не загружен в GitHub, команда не заработает. Лучше сначала прочитать код скачанного скрипта. Для постоянных автоматизированных развёртываний стоит фиксировать конкретный commit вместо меняющейся ветки `main`.

Скрипт использует `C.UTF-8` **только для процесса установки**, без изменения системной локали (`update-locale` не запускается). Он устанавливает `console-setup`, `console-setup-linux`, `kbd` и шрифт Linux-консоли Terminus / Uni2 для кириллицы. Собственные заголовки этапов — голубые, предупреждения — жёлтые, ошибки — красные, успешный итог — зелёный, если терминал поддерживает ANSI-цвета. Системные сообщения Ubuntu и других программ останутся на языке, заданном их окружением (для наших команд обычно на английском). Некоторые веб-консоли используют собственные шрифты и не поддерживают эту настройку; в таком случае доступен `SETUP_LANG=en`. Вопросы стороннего установщика 3AX-UI могут оставаться английскими.

Обновление пакетов идёт без вопросов о замене файлов конфигурации `dpkg`: действующие версии (включая `/etc/cloud/cloud.cfg`) сохраняются автоматически через `--force-confold`. Перед обновлением `cloud.cfg` копируется в каталог резервных копий. Автоматическое сохранение старой конфигурации может потребовать последующего ручного просмотра новых `.dpkg-dist` файлов. Установщик 3AX-UI остаётся интерактивным.

После подготовки шрифта скрипт запросит подтверждение `ДА` или `YES`, доверенный IPv4 для исключения из Fail2ban, **имя нового SSH-пользователя**, пароль для локального `sudo` (дважды, ввод скрыт, минимум 12 символов) и **публичный SSH-ключ** одной строкой (`ssh-ed25519 AAAA...`). Приватный SSH-ключ нельзя вставлять в консоль или загружать на GitHub. Ключ проверяется через `ssh-keygen`, затем сохраняется в `~/.ssh/authorized_keys` с правильными владельцем и правами. Новый пользователь добавляется в группу `sudo`. **Проверка SSH перед отключением старого доступа:** после создания пользователя скрипт временно оставляет открытыми порты `22` и `1335`, и в команде проверки **принудительно запрещает парольную аутентификацию**. Из второго терминала на своём компьютере нужно проверить вход с вашим приватным ключом `ssh -o PreferredAuthentications=publickey -o PasswordAuthentication=no -o KbdInteractiveAuthentication=no -p 1335 USER@IP_СЕРВЕРА`, затем в новом SSH-сеансе выполнить короткую команду `sudo touch /run/3ax-ssh-verified`. После успешного ввода пароля sudo вернитесь в веб-консоль хостинга и нажмите Enter. Только после нахождения проверочного файла установщик отключит SSH-доступ root и по паролю, закроет 22/tcp и продолжит. Если вход не работает, **не подтверждайте проверку**: на этом этапе старый доступ сохранён. При необходимости нажмите Ctrl+C и разберитесь с SSH, не закрывая веб-консоль. Маркер подтверждения находится по постоянному короткому пути `/run/3ax-ssh-verified`; скрипт удаляет старый маркер перед каждой проверкой и после успешного завершения этапа. Каталог `/run` уже существует в Ubuntu. Создавать его нужно **только в новом SSH-сеансе после реального входа по ключу и успешной команды `sudo`**. Само наличие файла не является техническим доказательством подключения извне и не проверяет веб-панель.

После этого установщик панели задаст собственные вопросы. В актуальном установщике 3AX-UI выбирайте:

- **Debug mode:** `N` (обычная установка)
- **Customize Panel Port:** `Y`
- **Panel Port:** `13350`
- **ACME HTTP-01 port:** `80` (если выбран вариант выдачи сертификата через этот порт)

После установки скрипт проверит сервис x-ui, открытый порт 13350, WebBasePath и SSL-сертификат. Затем **попросит выбрать для каждого из трёх параметров** способ задания: **1 — сгенерировать случайно** (по умолчанию, достаточно Enter) либо **2 — ввести самостоятельно**:

- Логин панели — латиница, цифры, `_`, `-`; от 4 до 32 символов; должен начинаться с латинской буквы.
- Пароль панели — при ручном вводе минимум 12 символов, ввод скрыт и требуется подтверждение; при генерации — 30 случайных букв и цифр.
- **Корневой путь URL (WebBasePath)** — при ручном вводе один сегмент из 6–64 латинских букв, цифр, `_`, `-` (например, `/mySecretPanel/`); при генерации — случайные 24 символа. Это **путь** после адреса сервера и порта, а не доменное имя.

После выбора скрипт применит параметры штатной командой `x-ui setting`, явно сохранит `13350` как порт панели, перезапустит её, подождёт до 45 секунд появления TCP-порта и повторно сверит порт, доступность интерфейса не только на loopback и URL-путь и **выведет полную HTTPS-ссылку, логин и пароль только в итоговом блоке**. Адрес берётся из SAN установленного SSL-сертификата. Временный пароль, показанный сторонним установщиком 3AX-UI, после этого перестанет действовать. Свой пароль не публикуйте на GitHub и не сообщайте в чате. Скрипт не записывает итоговый пароль в отдельный лог или файл. Сохраните его самостоятельно в менеджере паролей. Если проверка не пройдёт, будет указан этап ошибки.

### Если веб-консоль по-прежнему показывает квадраты

В таком случае шрифт, вероятно, задаёт интерфейс хостинга. Запустите локальную копию скрипта в режиме ASCII/English:

```bash
sudo env SETUP_LANG=en bash /tmp/3ax-setup.sh
```

На Ubuntu 22.04/24.04 наличие UTF-8 не гарантирует, что веб-консоль хостинга умеет рисовать русские буквы. Если есть возможность, используйте обычный SSH-терминал с UTF-8. Если ранее версия v0.3 изменила системный язык сервера, новая версия **не возвращает его автоматически**: для возврата исходного языка нужно отдельно изменить системную локаль.

## Что настраивается

| Компонент | Настройка |
| --- | --- |
| Ubuntu | 22.04 / 24.04 |
| SSH | Новый пользователь с `sudo` и `authorized_keys`; **проверка входа по ключу** до закрытия 22; итоговый порт **только 1335/tcp**; `PermitRootLogin no`, `PubkeyAuthentication yes`, `PasswordAuthentication no`, `KbdInteractiveAuthentication no`, `AuthenticationMethods publickey` |
| Fail2ban | `sshd`, 3 попытки за 600 секунд, бан 43200 секунд |
| Fail2ban ignoreip | `127.0.0.1/8 ::1` и доверенный IPv4, вводимый при запуске |
| UFW | 1335/tcp, 13350/tcp, 13133/tcp+udp, 20304/udp, 13131/udp, 80/tcp; входящий порт **22/tcp запрещён** |
| Порт 443 | Не открывается |
| Основные DNS | Cloudflare: 1.1.1.1, 1.0.0.1, 2606:4700:4700::1111, 2606:4700:4700::1001 |
| Резервные DNS | Quad9: 9.9.9.9, 149.112.112.112, 2620:fe::fe, 2620:fe::9 |
| Nginx | Останавливается; вызов установки nginx в 3AX-UI отключается |
| Ядро / DKMS | linux-generic + linux-headers-generic только при совместимом generic-ядре; dkms всегда |

DNS: `FallbackDNS` в systemd-resolved применяется при отсутствии других DNS-серверов, а **не как строгая очередь после Cloudflare**. Если DHCP продолжает передавать свои DNS, нужен Netplan `use-dns: false`. Скрипт пытается изменить Netplan только при запуске **не через SSH**, при распознанной DHCP-конфигурации и с подтверждением `netplan try`. В остальных случаях записывает только настройки `systemd-resolved` и предупреждает об ограничении.

## Если после восстановления базы не открывается панель

Восстановленная база **может** содержать настройки другого сервера: порт, базовый URL-путь, учётные данные и пути к SSL-сертификатам. Это не означает, что панель заблокирована UFW. Также возможны ошибка запуска, несовместимая база или ожидание перезапуска.

**Сначала выполните только безопасные команды чтения** в консоли хостинга (не вставляйте сюда пароли или содержимое базы):

```bash
sudo systemctl status x-ui --no-pager -l
sudo /usr/local/x-ui/x-ui setting -show true
sudo /usr/local/x-ui/x-ui setting -getListen true
sudo /usr/local/x-ui/x-ui setting -getCert true
sudo ss -ltnp | grep -E 'x-ui|:13350' || true
sudo ufw status verbose
sudo journalctl -u x-ui -n 40 --no-pager
```

Если настройки показывают другой порт, браузер по `13350` не откроет панель. Если порт слушает только `127.0.0.1`, к ней не подключиться извне. Если `x-ui` упал, его причина обычно видна в `journalctl`. При восстановлении SSL сертификаты, расположенные на прежнем VPS, могут отсутствовать. **Не выполняйте `x-ui setting -reset true` или удаление базы в качестве первого шага:** это сбрасывает параметры и может повредить восстановление. Сначала выясните точную причину; при необходимости скопируйте базу и настройки перед исправлением.

Новая версия установщика исправляет **проверку в конце первоначальной установки**, но сама по себе не защищает от изменений, внесённых позднее вручную при восстановлении базы данных.

## После установки

Финальный блок выводит только результат (`Установка завершена. Ошибок нет.` либо этап ошибки), предупреждения при необходимости, URL, выбранный или сгенерированный логин и пароль 3AX-UI, а также имя SSH-пользователя и пример подключения. **Пароль пользователя для `sudo` не выводится повторно** и не записывается на диск. Если нет сертификата, панель не запущена или выбран неверный порт — итоговый блок покажет ошибку, а не успешный вход.

1. **Не закрывайте веб-консоль хостинга.** Откройте отдельный терминал на своём компьютере и проверьте `ssh -p 1335 ИМЯ_ПОЛЬЗОВАТЕЛЯ@IP_СЕРВЕРА` с соответствующим приватным ключом. Отключение root, парольного SSH и 22/tcp уже выполнено после отдельной проверки в середине установки. Проверить реальное внешнее подключение изнутри VPS нельзя.
2. Убедитесь, что веб-панель открывается на фактически выбранном порту `13350` и SSL работает.
3. Проверьте `sudo ufw status verbose`, `sudo fail2ban-client status sshd`, `sudo systemctl status x-ui` и `resolvectl status`.
4. Если после обновления ядра требуется перезагрузка, проведите её после проверки доступа.

## Замечания по безопасности

- Подразумевается чистый VPS, а не уже настроенный производственный сервер.
- Дополнительные фильтры у хостинга (security groups) настраиваются отдельно: UFW их не заменяет.
- Интерфейс панели по `13350/tcp` открыт для всех IP, как в исходном наборе команд. При возможности ограничьте доступ доверенными адресами.
- Порт 22 закрывается **только после подтверждения нового SSH-подключения по ключу и выполнения sudo**. Если публичный SSH-ключ не соответствует приватному ключу или 1335 заблокирован у хостинга, скрипт оставит старый доступ до проверки. Не закрывайте веб-консоль до подтверждения.
- Репозиторий публичный: никакие сертификаты, пароли, личные ключи и журнал с секретами сюда не загружать.
- Программа 3AX-UI загружается из стороннего репозитория `coinman-dev/3ax-ui`; перед развёртыванием в продакшене следует проверить исходники и изменения установщика. Скрипт сверяет форму вызова `install_nginx`, но это **не заменяет** аудита стороннего кода.

**Важно:** если на сервере ранее при запросе `cloud.cfg` уже выбрали `Y`, новая версия скрипта не откатывает эту замену. Проверьте сетевые настройки и сохраните снимок VPS перед перезагрузкой.
